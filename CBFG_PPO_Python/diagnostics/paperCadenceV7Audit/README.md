# 主論文に沿った学習フローへの復帰

コード本体に適用済み。今回の変更は主論文Algorithm 1・Table IIIの記載に沿うことを優先する。既存モデル・150,000 stepの結果・安定化試験の結果は上書きしていない。変更前コードは `diagnostics/paperCadenceV7Audit/before` に保存した。

## 既定の学習フロー

1. 環境をリセットし、空のエピソード用Bufferから開始。
2. Actorの参照行動 → MPC → CBF補正 → 環境を進める。
3. 状態、元の行動とtanh前のサンプル、CBF補正、報酬、次状態などを保存。
4. 終了または時間制限まで収集する。その間にpolicyを更新しない。
5. Advantageを計算し、ミニバッチ128で40 epoch全て実行。非介入はPPO、介入はBC、criticはTD損失を用いる。
6. Bufferを空にして次のエピソードへ進む。

| 設定 | 現在の既定値 | 根拠・扱い |
|---|---|---|
| 更新タイミング | 終了したエピソード毎 | Algorithm 1 |
| 更新epoch | 40、早期終了なし | Table III |
| Buffer容量 | 3072 | Table III。著者の容量の具体的利用法は未確定 |
| バッチサイズ | 128 | Table III |
| 学習率 / 割引率 | 0.0006 / 0.99 | Table III |
| KL上限・取消 | 無効 | 追加安定化策を外した |
| 勾配ノルム制限 | 無効 | 主論文未記載の追加策を外した |
| Advantage正規化 | 無効 | 主論文の損失スケールを維持 |
| Entropy bonus / std下限 | 追加なし | 未記載の目的項・下限は追加しない |

以前の3072サンプル単位の収集は、`--update-schedule rollout`で選ぶ実験用機能としてだけ残した。これは主論文への忠実な再現モードではない。既定で起動した場合はepisode方式となる。tanh前の行動保存・確率比の整合性修正、診断ログは維持した。KL値の記録は学習を止めたり更新を変更したりしない。

総150,000 stepの予算で最後のエピソードが未完了になった場合は、その軌跡を更新に使わない。論文はこの端数処理を規定していないため、これは「終了後に更新する」フローを優先した補完条件である。実際に最後に更新したstepと使用しなかった末尾sample数をモデル情報に記録する。

## 検証

77項目のテストが通過。既定でエピソード毎に更新すること、未完了の最終軌跡を除外すること、129 sampleでは2ミニバッチ×40 epoch＝80回のoptimizer stepを最後まで実行すること、勾配制限が呼ばれないこと、未更新policyの確率比が1になることを確認した。実環境の完了した1エピソードによる学習・モデル選択・保存・厳密な互換性検査も確認した。

今回、150,000 stepの本学習は実行していない。変更前のモデルを今回の設定で作られたものとして使わないよう、実装識別子を `cbfg-ppo-paper-cadence-v7` に更新した。再開学習と通常シミュレーションの厳密な検査は、旧v5/v6を拒否する。

## 残る未記載部分

学習フローを記載に合わせたことと、コード全体が完全に著者実装と一致することは別である。CBF補正から参照速度・headingへの教師行動変換、介入閾値の座標・補正量の扱い、MPCの重み・horizon・wheelbase、CBF楕円寸法・境界・solver失敗時の処理、行動/観測の正規化、交通の生成範囲・成功判定、初期探索分散・モデル選択などの既存の補完条件は残る。GAEは引用[47]を参考にしているが、主論文がその推定法を採用したとは確認できない。これらを「論文の確定値」とは表示しない。

今回、成功率に合わせるために報酬・教師行動・CBF制約等を変更していない。忠実な更新方式に戻すことで、以前確認した分散縮小が再発しないとは約束できない。結果が異なっても、まず未記載条件・実装差分として調べ、安定化策を著者の設定として扱わない。

## 新規学習

プロジェクトのルートをVSCodeで開き、terminalで実行する。`main/mainLearning.py`の三角実行でも既定はepisode方式・5m/s・150,000 stepとなる。以下は既存結果を保存するために出力先を分けた例。

```powershell
python -m main.mainLearning --speed 5 --total-steps 150000 --seed 0 --output-dir results/runs/paper_cadence_v7_speed5_seed0
python -m main.mainSimulation --speed 5 --model results/runs/paper_cadence_v7_speed5_seed0/models/bestPolicy.pt --episodes 50 --seed 10000 --output-dir results/runs/paper_cadence_v7_speed5_seed0/evaluation
```

10m/sは両方の`--speed`と出力先名を10に変更する。旧モデルから`--resume`せず新規学習する。
